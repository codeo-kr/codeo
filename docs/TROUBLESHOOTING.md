# 코드오 트러블슈팅 가이드

이 문서는 운영 중 자주 생기는 문제를 빠르게 진단하기 위한 가이드입니다.

## 1. 접속이 안 된다

### 증상

- 휴대폰에서 페이지가 열리지 않음
- 같은 와이파이인데도 접속 실패
- localhost에서는 되는데 다른 기기에서는 안 됨

### 확인 순서

1. 서버 PC와 접속 기기가 같은 와이파이인지 확인
2. 접속 주소가 `localhost`가 아니라 서버 PC의 LAN IP인지 확인
3. 서버가 실제로 떠 있는지 확인
4. 4000, 5173 포트가 방화벽에 막히지 않았는지 확인
5. Vite가 5174로 올라갔는지 확인

### 정상 주소 예시

- 프론트: `http://172.30.1.7:5173`
- API: `http://172.30.1.7:4000`

## 2. 데이터가 없어 보인다

### 원인 후보

- 다른 기기에서 예전 localStorage만 보고 있음
- 서버 `server/data.json`보다 오래된 백업을 보고 있음
- 최신 데이터가 아직 서버에 동기화되지 않음
- 서버를 안 띄운 상태에서 브라우저만 열린 경우

### 확인 순서

1. `GET /api/health` 확인
2. `GET /api/db`에서 실제 데이터 개수 확인
3. `server/data.json`과 백업 파일의 날짜를 비교
4. 브라우저 localStorage가 아닌 서버 데이터 기준으로 다시 확인

### 기억할 점

- 서버가 있는 경우 서버가 원본입니다.
- localStorage는 보조 캐시입니다.
- 백업 파일은 특정 시점의 스냅샷입니다.

## 3. 저장이 반영되지 않는다

### 증상

- 입력했는데 새로고침하면 사라짐
- 다른 기기에는 안 보임
- 저장은 됐다고 나오는데 데이터가 유지되지 않음

### 확인 순서

1. 로그인 상태인지 확인
2. 서버 프로세스가 살아 있는지 확인
3. `server/data.json`이 쓰기 가능한지 확인
4. 서버 로그에 `PUT /api/db` 또는 감사 로그가 남는지 확인
5. 브라우저 콘솔에 동기화 실패 오류가 있는지 확인

### 주의

- 예전처럼 전체 DB를 통째로 덮어쓰면 여러 사용자 환경에서 데이터가 쉽게 꼬입니다.
- 현재는 patch 기반 저장이므로, 저장 실패 시 네트워크 문제나 토큰 문제부터 의심합니다.

## 4. 로그인 실패

### 증상

- 아이디/비밀번호가 맞는데도 로그인 안 됨
- 401 또는 403 오류가 뜸

### 확인 순서

1. 서버가 실행 중인지 확인
2. 환경변수 `JWT_SECRET`이 비어 있지 않은지 확인
3. 프론트의 `VITE_API_BASE_URL`이 올바른지 확인
4. CORS 허용 도메인이 맞는지 확인
5. 브라우저 세션이 꼬였으면 로그아웃 후 다시 시도

### 기본 계정

- 원장: admin / Admin1234!
- 강사: teacher / Teacher1234!
- 상담: counsel / Counsel1234!

## 5. 포트 충돌

### 증상

- `npm run dev:full` 실행 시 5173 대신 5174로 올라감
- 이미 사용 중인 포트라는 메시지가 나옴

### 해결

1. 기존 프론트 프로세스를 종료
2. 서버/프론트 프로세스가 남아 있으면 정리
3. 다시 실행

### 참고

- 5173이 점유 중이면 Vite가 5174로 자동 전환할 수 있습니다.
- 그 경우 LAN 접속 주소도 5174로 바뀝니다.

## 6. 보강이나 회차가 이상하다

### 증상

- 결석예정이 회차에 잡힘
- 보강이 없어졌거나 중복 생성됨
- 학생 사용 회차가 기대와 다름

### 확인 순서

1. `결석예정`은 미차감인지 확인
2. 정규 출결만 회차 계산 대상인지 확인
3. 보강 등록/취소 시 연결된 출결이 같이 바뀌는지 확인
4. 학생별 `sessionOffset` 값이 들어가 있는지 확인

### 관련 위치

- 회차 규칙 안내: [src/App.tsx](../src/App.tsx)
- 출결 저장 로직: [src/App.tsx](../src/App.tsx)
- 보강 저장 로직: [src/App.tsx](../src/App.tsx)
